# X5.2b (f697f0e): the glow's box filter (`glow.down`, `low` only) and its four
# blurs (`glow.blur`) are our draws, compared with the Babylon draws they
# replaced under the same names. Three fields differ by construction:
# - `pipeline.call`: ours `createRenderPipelineAsync` ahead of the frame,
#   Babylon's `createRenderPipeline` at its first draw.
# - `bundle`: Babylon's draw was recorded into a render bundle; ours is a
#   bundle-list item run on the pass encoder itself (seam item 3).
# - `viewport`: Babylon set the whole target before its bundle; ours sets none,
#   which a render pass defaults to (the same `[0, 0, w, h, 0, 1]`).
**.draws[stage=glow.*].pipeline.call
**.draws[stage=glow.*].bundle
**.draws[stage=glow.*].viewport

# opens as Babylon's `_finalizeFrame` opened it for Babylon's last pass;
# Babylon's prefix writes the grade's input (`camera.outputRenderTarget`, set
# only across the post phase), cleared as Babylon's `activate` cleared it. Every
# pass, its attachments, load ops, clears, labels and hashes are compared, and
# every field of the grain's draw but X5.2b's three, which differ by
# construction for the same reasons:
**.draws[stage=grain].pipeline.call
**.draws[stage=grain].bundle
**.draws[stage=grain].viewport
# And Babylon's own bookkeeping, which X5.2c1 moves by design (`chain` is the
# CPU facts beside a frame, not a draw): the camera's list no longer holds the
# grade, and the blur's toggle no longer takes the grade off and re-appends it,
# so the list is shorter and has fewer holes (`list`); a grade switched off is
# no longer a detached Babylon pass (`off`); and the grade has no `attached`
# (`slots.grade.attached`) — its switch is its stage's `active()`.
**.chain.list
